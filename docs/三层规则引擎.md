# CaddyGuard 三层规则引擎

本文描述 CaddyGuard `engine.go` 的实现，语义与 nginxguard `engine.lua` 对齐。三层分别是基础检测器（L1）、组合规则（L2）和动作执行（L3）。组合规则文件为 `rule-config/combo.jsonl`。

## 1. 请求处理顺序

```text
CaddyGuard ServeHTTP
  └─ runChecks
      ├─ IP 白名单命中 → 放行
      ├─ L2/L3：读取并评估 combo.jsonl
      │   ├─ 按文件顺序执行规则表达式
      │   ├─ 表达式叶子按需调用 L1 检测器，命中事实缓存到请求 state
      │   └─ 命中规则时执行 L3 动作；终止请求的动作立即返回
      └─ 传统检测链（复用 L1 结果缓存）
          ├─ dynamic_black_ip → black_ip
          ├─ whiteurl 规则和请求类型判断
          └─ user_agent → header → referer → cc → file_upload → url
             → url_args → cookie → post（受白名单跳过项和 bodyless 配置影响）
```

IP 白名单优先于组合规则，因此白名单 IP 不会被组合规则检测。组合规则先于传统阻断流程，因此可先记录、打分或拦截；若组合规则没有终止请求，传统流程仍会继续。传统流程复用同一请求的 L1 检测结果，不会重复扫描。

## 2. L1：基础检测器

| 名称 | 检查内容 | 相关开关 |
|---|---|---|
| `url` | URL 路径规则 `url.rule` | `url_check` |
| `url_args` | 查询参数规则 `args.rule` | `url_args_check` |
| `post` | 表单参数或请求体规则 `post.rule` | `post_check`；GET/HEAD/OPTIONS 默认跳过 |
| `header` | 请求头规则 `header.rule` | `header_check` |
| `cookie` | Cookie 规则 `cookie.rule` | `cookie_check` |
| `user_agent` | User-Agent 规则 `useragent.rule` | `user_agent_check`；UA 白名单可跳过 |
| `referer` | Referer 规则 `referer.rule` | `referer_check` |
| `file_upload` | multipart 文件名/扩展名规则 `fileext.rule` | `file_upload_check`；bodyless 方法默认跳过 |
| `cc` | CC 限速检测 | `cc_check` |
| `black_ip` | 静态黑名单 IP `blackip.rule` | `black_ip_check` |
| `dynamic_black_ip` | 动态封禁 IP | `cc_block_ttl` |

检测器复用传统检测实现，返回命中事实（日志标签、rule tag、data）或未命中。结果按请求缓存在请求 state 中，一个请求中同一检测器最多执行一次。组合表达式使用三态结果：命中、未命中、未知；检测器异常记为未知。

为避免“检测被关闭或跳过”被取反成命中，规则校验禁止 `NOT` 子树包含任何 L1 检测器；`NOT` 仍可用于内联请求条件。

## 3. L2：组合规则与表达式

### 文件格式和加载

`combo.jsonl` 使用 JSON Lines 格式：每个非注释行是一条 JSON 规则，空行和以 `#` 开头的行忽略。域名配置存在 `rule_dir` 时，先读取域名规则目录的 `combo.jsonl`；该文件不存在时回退全局 `rule_dir`。文件存在但为空表示该域名关闭组合规则。

热加载与其它规则文件共享节流窗口（2 秒）；文件版本由 mtime 纳秒 + 大小组成。无需 reload Caddy。

规则必须有非空字符串 `id` 和 `if` 表达式；`enabled: false` 会跳过。加载时校验检测器名、内联条件名、操作符、参数类型、`AT_LEAST` 范围，并预编译正则；无效 JSON、表达式、正则或 action 会记录错误并忽略该条规则。表达式嵌套深度上限 16。

### 规则对象

```json
{"id":"scanner-on-api","if":["AND","user_agent",{"cond":"uri","op":"prefix","value":"/api/"}],"action":"LOG"}
```

| 字段 | 含义 |
|---|---|
| `id` | 规则标识；写入组合规则日志标签 |
| `if` | 必填表达式 |
| `action` | `BLOCK`、`LOG`、`ALERT`、`SCORE`、`CHALLENGE`；缺省 `BLOCK`（不区分大小写） |
| `score` | `SCORE` 的加分值；缺省 10。`SCORE` 必须为正数，否则整条规则忽略 |
| `enabled` | 明确设为 `false` 时禁用 |

规则按文件顺序执行。`LOG`、`ALERT`、未达到阈值的 `SCORE` 不会停止后续组合规则；`BLOCK`、`CHALLENGE` 或达到分数阈值时终止请求。分数保存在请求 state 中，不跨请求累计。

### 表达式

```json
"url"
["AND", "url_args", {"cond":"method","op":"eq","value":"POST"}]
["OR", "url", "header"]
["NOT", {"cond":"ip","op":"re","value":"^10\\."}]
["AT_LEAST", 2, "url", "url_args", "post", "header"]
```

- 字符串叶子：调用同名 L1 检测器。
- `AND` / `OR`：短路求值。
- `NOT`：唯一内联条件取反；不能包含 L1 检测器。
- `AT_LEAST`：从第二个参数读取数量 `n`，后续子表达式中至少 `n` 个为真。

运算符名称区分大小写。`AND`、`OR`、`NOT` 和 `AT_LEAST` 会传播未知状态。

### 内联请求条件

| `cond` | 请求数据 |
|---|---|
| `uri` | `r.URL.Path` |
| `args` | `r.URL.RawQuery` |
| `method` | 请求方法 |
| `protocol` | `r.Proto`（如 `HTTP/1.1` / `HTTP/2.0`） |
| `header` | 请求头拼接成的 `名称: 值` 文本（含 Host） |
| `cookie` | Cookie 请求头 |
| `body` | 请求体 |
| `ip` | 客户端 IP |
| `header_count` | 请求头数量（含 Host，重复头按值计数） |
| `content_type` | Content-Type |
| `content_length` | Content-Length |
| `transfer_encoding` | Transfer-Encoding（包含 chunked 回退） |

普通字段支持：

| `op` | 语义 |
|---|---|
| `re` | Go RE2 正则搜索；**默认忽略大小写**（默认加 `(?i)`）。`flags` 显式覆盖，或 `case_sensitive: true` 关闭 |
| `eq` | 值相等比较；`method`/`protocol` 默认区分大小写，其他字段默认忽略；可用 `icase` 覆盖 |
| `contains` | 字面子串搜索；**默认忽略大小写**，`icase: false` 关闭 |
| `prefix` | 字面前缀比较；**默认忽略大小写**，`icase: false` 关闭 |
| `exists` | 字段存在即为真（空字符串也算存在） |

`header_count` 专用 `gte`、`lte`、`eq` 比较数量。

**大小写**：匹配内容默认不区分；检测器名、`AND`/`OR`/`NOT`/`AT_LEAST`、`cond`/`op` 字段名区分大小写；`action` 不区分；`config.json` 的 `"on"`/`"off"` 必须小写。

请求体读取缓存到请求 state，最多保存/扫描前 2 MiB；更大的 body 标记为不完整。该上限固定为 2 MiB，不随 `post_body_scan_limit` 变化。对不完整 body：`re`/`eq` 得到未知；`contains` 在已扫描部分找到匹配可判真，否则未知；`prefix` 可在已读前缀足够时准确判断，否则未知。读取失败也得到未知。

## 4. L3：动作、日志和拦截

| 动作 | 行为 |
|---|---|
| `BLOCK` | 写 `Combo_BLOCK`；调用统一 `waf_output()` 并终止请求 |
| `LOG` | 写 `Combo_LOG`，继续处理 |
| `ALERT` | 写 `Combo_ALERT`，继续处理 |
| `SCORE` | 累计分值并写 `Combo_SCORE`；达到阈值时写 `Combo_SCORE_BLOCK` 并拦截 |
| `CHALLENGE` | 写 `Combo_CHALLENGE`，复用统一输出并终止请求（当前与 BLOCK 输出一致） |

分数阈值配置为 `score_block_threshold`，默认 0：

| 取值 | 行为 |
|---|---|
| `0` | 只累计并写 `Combo_SCORE`，不因 SCORE 拦截 |
| `1` | **开启拦截**：任意一次 SCORE 命中（累计 ≥1）即拦截，等价于开关 |
| `>1` | 同一请求累计达到该值才拦截（如 20/30） |

域名级可通过 `domain.json` 的 `score_block_threshold` 覆盖。组合日志标签是动作名，规则 `id` 作为日志中的 rule tag。

## 5. 当前规则与示例

`rule-config/combo.jsonl` 内置 2026-11 CVE 虚拟补丁（WordPress setup-config/upgrade、Apache mod_http2、Axis SOAP Fault、phpAfterShell upload_progress），默认 5 条 `BLOCK` 规则，均使用内联 URI/协议/请求头计数/请求体条件。

```json
{"id":"observe-post","if":["AND","post",{"cond":"method","op":"eq","value":"POST"}],"action":"LOG"}
{"id":"sqli-plus-rce","if":["AND","url_args","post"],"action":"SCORE","score":30}
```

建议把便宜的请求字段条件放在表达式前部，以便短路；先用 `LOG` 观察命中日志，再改为阻断动作。

## 6. 实现边界

- L1 缓存保证每请求最多执行一次检测器；规则文件/匹配缓存仍由各自 worker/进程级缓存负责。
- 组合规则入口位于传统检测之前，受 WAF 总开关和 IP 白名单顺序影响，但不会因为 `whiteurl.rule` 自动跳过；whiteurl 的跳过项只影响后续传统检测。
- 检测器异常被 recover 并标记为未知；在 `BLOCK`/`CHALLENGE` 规则中按未知状态拦截。
- `body` 内联条件使用引擎自身的 2 MiB 扫描上限，与 `post` 检测器的表单解析、文件扫描及超限策略不是同一实现。
- 正则使用 Go RE2，不支持 PCRE 的回溯引用/lookaround；这类规则会在加载期被丢弃。
- 域名级 `rule_dir` 的 `combo.jsonl` 优先于全局；存在时整份组合规则表来自该文件，不与全局合并。
